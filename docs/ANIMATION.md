# Lunelle · 动作与播放

本文描述本地开发版 v0.3.25 的当前行为。散步采用用户选定的第 19 版画面，后续试作和旧骨骼步态已退役；“第 19 版”指美术试作编号，不是应用版本号。

## 交互规则

自动活动默认开启，使用全屏散步。开启后，空闲约 8～12 秒才可能活动。全屏散步局限在当前显示器工作区，不自动跨屏，也不覆盖手动保存的位置。鼠标经过继续散步；点击、拖动、展开手账、打开设置或隐藏桌宠会停止或暂停活动。

人物点击区域不随动画变化。位置沿同一条显示时间轴更新；拖动即时跟手。左键随机触发动作 01–05；按住并拖动才进入动作 06。右键直接进入动作 08，不显示宠物右键菜单。面板展开后，以趴边立绘播放轻微呼吸与偶尔歪头。

## 动作

| 动作 | 播放方式 |
| :--- | :--- |
| 01 呼吸 | 每轮 4.2 秒，以坐姿底部为支点，上身纵向起伏约 2.2%，轻微横向舒展；吸气顶点短暂停留 |
| 02 眨眼 | 半闭、闭合短停、半睁、睁眼，约 340ms |
| 03 歪头 | 头肩连续变形，倾斜后回正 |
| 04 点头 | 轻微下俯，眼睛配合闭合与睁开 |
| 05 挥手 | 原坐姿局部肩臂合成，连续摆动后收回 |
| 06 拖动与落地 | 完整抱膝悬空姿态，松手连续接入缓冲与回坐 |
| 07 散步 | 第 19 版完整画面播放，保留其造型与八张腿部关键姿势 |
| 08 面板陪伴 | 右键直接触发，也可从托盘或设置进入，停止散步并展开手账；原始趴边立绘连续呼吸、歪头，双手固定在纸边。单击宠物仅互动。 |

## 第 19 版散步

实际目标决定行走朝向：向左移动时仅镜像散步 Canvas 中的角色像素，向右移动时恢复原图。换向不重置步态时间轴，不影响点击区域、面板或其他动作；停止散步后恢复原始朝向。

资源为 `assets/characters/walk-v19.webp`，640 × 640，216 帧。原始 20ms 帧间隔放慢至 30ms：一个左右步态周期 1.08 秒，含六轮步态与两次眨眼的完整素材为 6.48 秒。对应时间轴位于 `ui/walk-timeline.js`。

完整画面保留轻微重心起伏、发尾与裙摆跟随、抱枕缓冲和原定眨眼。216 帧包含细微动态采样，腿部仍以八张关键姿势为基础；它不等于 216 张重新绘制的腿部姿势，也不承诺真人步态精度。

`ui/pet-walk.js` 用本地 ImageDecoder 按帧解码到透明 Canvas，不再拆分腿部或执行骨骼拉伸、整图补帧。最多保留八张解码位图。真实散步按显示位置增量推进时间轴，停止移动时保持当前帧；设置预览按时间播放。减少动态效果设置固定显示首帧。较旧运行时可使用浏览器原生 WebP 回退。

原始预览含白底，运行素材只做透明背景转换。角色主体在白底上合成后的 RGB 与原版逐帧一致，另清理透明区的微小孤立散点，转换审计保存在 `assets/characters/walk-v19.json`。文档预览 `docs/images/walk-v19.webp` 为同一资源的第一轮步态，不包含后续眨眼。

## 进入、中断与退出

常规动作自带起势和收势；动作接管时保留当前画面，约 180ms 接入目标动作。散步退出也从当前 Canvas 抓取完整画面，再回到坐姿。拖动与面板可立即接管，旧动作不会排队补播。

## 验证与复现

`npm test` 检查素材摘要、帧数与时长、周期闭合、缩放后的位移同步，以及数据与窗口交互。`npm run test:ui` 检查实际 Electron 解码、透明背景、帧缓存、点击区域和停止/接管行为。

保留的制作目录为 `artifacts/walk-study-v19/`，包含源姿势、眼睛素材和重建脚本。导出帧与重复预览已清理，需要时可重新渲染；此目录不参与应用打包。

这些检查验证实现与素材一致性，不替代对步态观感的人工判断。
